# NEXUS VPN — Discord-бот для 3x-ui

Бот выдаёт VPN-подписки из панели 3x-ui по ролям Discord (Boosty сам выдаёт и
снимает роль подписчикам), ведёт пробный период, поддержку и мониторинг серверов.

## Файлы

| Файл | Что делает |
|---|---|
| `bot.py` | Команды, реакция на роли, фоновые задачи |
| `xui_api.py` | Работа с 3x-ui через официальный API по токену (основной режим) |
| `xui_client.py` | Запасной режим: работа с панелью через headless-браузер |
| `link_server.py` | HTTPS-переходник для кнопки «Добавить в Nexus» |
| `rf_check.py` | Проверка доступности серверов из РФ (check-host.net) |
| `db.py` | SQLite: подписки, пробные периоды, обращения |
| `tests/` | Тесты на заглушках панелей и Discord: `python tests/run_all.py` |
| `test_connection.py` | Проверка подключения к панелям без запуска бота |
| `deploy.sh` | Обновление на сервере: бэкап → git pull → перезапуск → откат при ошибке |
| `install_ubuntu.sh` | Первая установка на чистый сервер |
| `backup.sh` | Бэкап кода, `.env` и базы |
| `.github/workflows/deploy.yml` | Автообновление сервера после Push в GitHub |

## Как это работает

- Роль Boosty (`VPN_ROLE_NAME`) → бессрочная подписка, ссылка и QR приходят в ЛС.
- Роли для розыгрышей и подарков (`VPN_GIFT_ROLES`) дают такой же доступ, но их
  выдаёте и снимаете вы сами — Boosty их не трогает. VPN работает, пока у человека
  есть хотя бы одна из ролей.
- Роль `VPN Trial` → пробный период на `TRIAL_DAYS` дней, один раз на человека.
  Срок идёт с первого подключения. За 2 дня и за 1 день до конца бот напоминает
  в ЛС (со ссылкой `BOOSTY_URL`), по окончании удаляет клиента и снимает роль.
- С trial купили подписку → пробный клиент заменяется постоянным.
- Роль сняли или человек вышел с сервера → через `REVOKE_GRACE_MINUTES` минут
  (по умолчанию 15) клиент удаляется со всех серверов. Если роль вернули раньше,
  ничего не меняется, ссылка остаётся прежней.
- Каждые `SYNC_INTERVAL_MINUTES` минут бот сверяет роли с подписками и догоняет
  то, что пропустил: досоздаёт клиентов на серверах, которые были недоступны,
  восстанавливает пропавших из панели, доводит незавершённые удаления.
- Роли действуют только на вашем сервере (`GUILD_ID`, иначе `TEST_GUILD_ID`).

**Защита от массового удаления.** За час бот отзывает не больше
`REVOKE_LIMIT_PER_HOUR` подписок (по умолчанию 20%, но не меньше 2). Если ролей
сняли больше (сбой Boosty, кто-то случайно снял роль у всех), остальные удаления
ждут: в админ-канал приходит сообщение. Роли сняты по ошибке — верните их, и
удаления отменятся сами. Всё верно — `/sync confirm:True`.

**Если панель недоступна.** Бот запускается и без неё (поддержка, рассылка и
статистика работают), каждую минуту пробует подключиться и сообщает в админ-канал,
когда панель вернулась. Ошибка панели никогда не считается «клиента нет»: пока
сервер не ответил, бот ничего не удаляет и пробный период не сжигает.

## Режим API (рекомендуется)

В панели: **Настройки → Безопасность → API Token** → создать токен (scope
`admin`) → вписать в `.env` как `XUI_API_TOKEN`. С токеном бот работает через
официальный API: мгновенно, без браузера (минус ~300 МБ памяти) и без
зависимости от вёрстки панели. Только в этом режиме работают второй сервер,
перевыпуск ссылки, `/ips` и контроль шаринга.

Перед переключением проверьте: `.venv/bin/python test_connection.py` — скрипт
проверит токены всех серверов и сделает пробный цикл «создать → удалить» тестового
клиента. Если токен не задан, бот работает по-старому, через браузер.

## Второй сервер

Заполните блок `XUI2_*` в `.env` (адрес панели, путь, адрес подписок, токен).
Бот сам создаёт клиента на втором сервере и добавляет его подписку как
**внешнюю** в подписку основного — у пользователя одна ссылка на обе локации
(то же, что вы делали вручную через «Изменить клиента → Ссылки → Добавить внешнюю
подписку»). Ссылки, добавленные вручную, бот не трогает. Для уже выданных
подписок второй сервер добавится при ближайшей сверке. Третий сервер — `XUI3_*`.

## Команды

Для всех:
- `/myvpn` — подписка, срок, трафик по всем серверам, ссылка и QR. Под ней:
  **инструкция по подключению** (Android, iPhone, Windows, macOS) и кнопка
  **«Перевыпустить ссылку»** (если ссылка утекла: старые конфиги перестают работать).
- `/support [тема]` — открывает приватную ветку с админами в канале
  `SUPPORT_CHANNEL_ID`; закрывается кнопкой в ветке.
- `/status_server` — карточка: нагрузка, Xray и **доступность из РФ** по каждому
  серверу. Проверка через узлы check-host.net в России показывает, не заблокирован
  ли IP/порт; блокировку протокола по DPI так увидеть нельзя.

Для админов (`ADMIN_ROLE_NAME`):
- `/announce` — рассылка подписчикам в ЛС (всем / платным / пробным), с предпросмотром.
- `/ips @user` — IP-адреса подключений. Раз в час бот сам сообщает в админ-канал,
  если с одной подписки за сутки было больше `SHARING_IP_THRESHOLD` разных IP.
- `/vpn_stats` — сколько подписок сейчас (Boosty и розыгрыши), сколько людей начали
  пробный период за 30 дней и за всё время, сколько из них потом купили на Boosty
  (конверсия), сколько ушли с Boosty, и ответы на опрос.
- `/audit` — состояние панелей и фоновых задач, посторонние серверы, ожидающие
  удаления, клиенты в панелях без записи в базе (`/audit delete_orphans:True`
  удаляет их).
- `/sync` — сверка сейчас; `/sync confirm:True` — подтвердить удаления, которые
  бот приостановил из-за лимита.
- `/revoke @user`, `/reset_trial @user`.

**Опрос после пробного периода.** Когда пробный период заканчивается без покупки,
вместе с сообщением об окончании приходят кнопки: «Дорого», «Медленно или
нестабильно», «Не получилось подключить», «Пока не нужен», «Другое» (с полем для
комментария). Ответ попадает в `/vpn_stats` и в админ-канал. Кнопки работают и через
несколько дней, и после перезапуска бота.

Права бота в Discord: Server Members Intent (Developer Portal); **выключите
«Public Bot»** (Developer Portal → Bot), чтобы бота не могли добавить на чужой
сервер; роль бота выше
`VPN Access`/`VPN Trial` с правом «Управление ролями»; в канале поддержки —
«Создавать приватные ветки», «Отправлять сообщения в ветках», «Управлять ветками».

## Кнопка «Добавить в Nexus»

Discord пускает в кнопках только https-ссылки, поэтому бот сам поднимает
маленькую страницу-переходник: `https://<домен>:<порт>/add/<subId>`. Она сразу
открывает приложение ссылкой `nexus://import?url=<подписка>` — Nexus спросит,
добавить ли подписку. Если приложение не открылось, на странице есть «Открыть ещё
раз», «Скачать Nexus» и копирование ссылки.

Кнопка появляется в `/myvpn` и в личных сообщениях при выдаче, переходе с trial и
перевыпуске. Страница открывается только для подписок, которые есть в базе
бота: после перевыпуска или удаления старая кнопка показывает «Ссылка устарела».
С одного IP — не больше 30 открытий в минуту и 10 неверных ссылок за 10 минут,
чтобы ссылки нельзя было подобрать перебором.

Настройка — блок `NEXUS_LINK_*` в `.env` и открытый порт в фаерволе. Сертификат
берётся тот же, что у панели; продление подхватывается автоматически. Без
`NEXUS_LINK_CERT` и `NEXUS_LINK_KEY` переходник слушает только `127.0.0.1`
(чтобы ссылка подписки не шла по сети открытым текстом) — тогда снаружи нужен
nginx с https. Если задан только один из двух файлов, переходник не запускается.

## Оповещения админам

`ADMIN_LOG_WEBHOOK_URL` — вебхук закрытого канала. Туда приходят ошибки выдачи и
удаления, итоги сверки, падение Xray, недоступность сервера из РФ, подозрение на
шаринг, новые обращения и итоги рассылок. Тексты ошибок не содержат cookie,
заголовков и HTML панели, а в `bot.log` не пишутся адреса запросов (секретный путь
панели и subId подписок).

`DB_BACKUP_WEBHOOK_URL` — вебхук отдельного закрытого канала: раз в сутки бот
присылает туда копию базы.

## Установка (первый раз)

```bash
cd /opt/3x-ui-to-discord
cp .env.example .env
nano .env
sudo bash install_ubuntu.sh
```

## Обновление

**Автоматически после Push** (GitHub Actions). Один раз настроить:
1. На сервере создать ключ для GitHub: `ssh-keygen -t ed25519 -f ~/.ssh/github_deploy -N ""`
2. Разрешить его: `cat ~/.ssh/github_deploy.pub >> ~/.ssh/authorized_keys`
3. Показать приватный ключ: `cat ~/.ssh/github_deploy` — скопировать весь текст.
4. В репозитории GitHub: Settings → Secrets and variables → Actions → New repository
   secret: `VPS_HOST` (IP сервера), `VPS_USER` (`root`), `VPS_SSH_KEY` (ключ из шага 3).
   Если SSH не на 22 порту — ещё `VPS_PORT`; если бот не в `/opt/3x-ui-to-discord` — `VPS_APP_DIR`.
5. Отпечаток сервера (защита от подмены): на сервере
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub | cut -d' ' -f2` → секрет `VPS_FINGERPRINT`.
6. Рекомендуется разрешить этому ключу только обновление: в `~/.ssh/authorized_keys`
   допишите перед ключом
   `command="bash /opt/3x-ui-to-discord/deploy.sh",no-port-forwarding,no-pty `
   — тогда утёкший ключ не даст выполнить на сервере ничего, кроме обновления.

Пока секреты не заданы, Actions только проверяет код и прогоняет тесты, а
выкладка пропускается (без красного статуса).

После этого каждый Push в `main`: проверка кода и тесты → бэкап → `git pull` → установка
новых зависимостей → перезапуск → проверка, что бот запустился. Если не запустился
за 90 секунд — автоматический откат на прошлую версию, а запуск в GitHub
(вкладка Actions) отмечается красным.

**Вручную:** `sudo bash /opt/3x-ui-to-discord/deploy.sh`

## Логи

Бот сам пишет `bot.log` с ротацией: до `LOG_MAX_MB` МБ, `LOG_BACKUPS` старых копий
(`bot.log.1`…), диск не забивается. Смотреть: `tail -f /opt/3x-ui-to-discord/bot.log`.
Аварийные ошибки запуска: `journalctl -u xui-discord-bot -n 50`.

## Бэкапы

`sudo bash backup.sh` — код, `.env` и консистентная копия базы в `/opt/backups`
(10 последних, только для root). `deploy.sh` делает бэкап перед каждым обновлением.

## Ограничения

- В режиме браузера изменения идут кликами по интерфейсу панели; после обновления
  3x-ui селекторы в `xui_client.py` могут потребовать правки. Режим API этого лишён.
- Переход trial → платная и перевыпуск выдают новую ссылку (панель пересоздаёт клиента).
- Сервис по умолчанию работает от root (так ставит `install_ubuntu.sh`). Unit
  ограничен (`NoNewPrivileges`, `ProtectSystem=full`, `UMask=0077`); для большей
  изоляции можно завести отдельного пользователя и указать его в `User=` unit-файла
  — `deploy.sh` его сохранит (нужен доступ этого пользователя к сертификату).
