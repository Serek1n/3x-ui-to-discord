# 3x-ui ↔ Discord бот для выдачи VPN-подписок

## Файлы

- `xui_client.py` — клиент 3x-ui на headless-браузере (Playwright). Логинится и
  выполняет запросы к API через настоящий Chromium, а не через HTTP-библиотеку -
  это нужно, если перед панелью стоит JS-защита, которую не пройти обычным
  запросом (см. раздел "Почему браузер" ниже).
- `db.py` — SQLite-хранилище: какая Discord-учётка каким клиентом в 3x-ui владеет.
- `bot.py` — слэш-команды и фоновая проверка истёкших подписок.
- `test_connection.py` — отдельный скрипт для проверки логина в панель без Discord.
- `install_ubuntu.sh` — установка бота как systemd-сервиса (включая браузер Chromium).

## Почему браузер, а не requests

Мы последовательно проверили: обычные заголовки (User-Agent/Origin/Referer) -
не помогло; имитация точного TLS-отпечатка настоящего Chrome (curl_cffi) -
тоже не помогло, при этом логин через настоящий браузер с того же IP проходил
всегда. Это возможно только если защита требует выполнения JavaScript
(например, челлендж наподобие тех, что ставят анти-DDoS/WAF-прокси) - такое
нельзя подделать без реального браузерного движка. Поэтому весь обмен с
панелью идёт через Playwright + Chromium.

Минус подхода: бот при старте держит открытым процесс headless-браузера
(дополнительно ~150-300 МБ памяти) и первый логин занимает 10-20 секунд
вместо долей секунды. Для VPN-бота с редкими командами это не критично.


## Как это работает

Выдача управляется ролями Discord (Boosty сам выдаёт и снимает роль подписчикам):

- Роль `VPN Access` есть → бессрочная подписка, ссылка и QR приходят в ЛС.
- Роль `VPN Trial` → пробный период на `TRIAL_DAYS` дней, один раз на человека.
  Срок идёт с первого подключения (Start After First Use); по окончании клиент
  удаляется, а роль `VPN Trial` снимается (`REMOVE_TRIAL_ROLE_ON_EXPIRY`).
- С trial купили подписку → пробный клиент заменяется постоянным (приходит новая ссылка).
- Роль сняли или человек вышел с сервера → клиент удаляется из 3x-ui.
- Лимит устройств — `DEVICE_LIMIT`.

**Сверка ролей.** При запуске и каждые `SYNC_INTERVAL_MINUTES` минут бот сверяет
роли всех участников с подписками: выдаёт доступ тем, кому роль выдали, пока бот
был выключен, и отзывает у тех, у кого роль сняли. Защиты:
- если удалить нужно больше половины подписок (например, отвалилась интеграция
  Boosty), удаление не выполняется, админам приходит предупреждение;
- если на сервере вообще нет ролей с указанными названиями, сверка пропускается.

**Надёжность работы с панелью.** Все операции с 3x-ui идут по очереди (одна
вкладка браузера), при истёкшей сессии бот сам перелогинивается, при падении
браузера — перезапускает его. Если клиента удалили в панели вручную, удаление
в боте считается успешным, запись в базе не «застревает».

Нужно в Discord Developer Portal: включить **Server Members Intent**. На сервере
роль бота должна быть **выше** ролей `VPN Access`/`VPN Trial` и иметь право
**«Управление ролями»** (для снятия Trial и `/revoke`).

## Команды бота

- `/myvpn` — тип подписки, срок, трафик, лимит устройств, ссылка и QR-код.
  Если роль есть, а подписки нет — бот выдаст её прямо в этот момент.
- `/status_server` — карточка статуса сервера (CPU, память, трафик, Xray) через
  вебхук `STATUS_WEBHOOK_URL`. Доступна админам и обладателям VPN-ролей,
  не чаще раза в `STATUS_COOLDOWN_SEC` секунд на человека.
- `/revoke @user` — [админ] удалить подписку и снять VPN-роли.
- `/sync` — [админ] запустить сверку ролей прямо сейчас и показать итог.
- `/reset_trial @user` — [админ] разрешить пробный период ещё раз.
- `/vpn_stats` — [админ] сколько платных и пробных подписок.

## Оповещения админам

Если задан `ADMIN_LOG_WEBHOOK_URL` (вебхук закрытого канала), бот пишет туда:
ошибки выдачи/удаления (например, оплативший клиент не получил VPN), итоги
сверки с изменениями, срабатывание защиты от массового удаления, остановку Xray.
Одинаковые ошибки повторяются не чаще раза в 6 часов.

## Happ

Если задан `HAPP_PROVIDER_ID`, в ссылку подписки добавляются `providerid` и `ping-type=tcp`.

## Бэкапы

`sudo bash backup.sh` — архив кода, `.env` и консистентной копии базы в
`/opt/backups` (хранятся 10 последних, доступны только root). Ежедневный бэкап
в 4:00 включается одной командой — она есть в начале `backup.sh`.

## Известные ограничения

- Панель блокирует изменяющие API-запросы, поэтому создание и удаление клиентов
  идут кликами по интерфейсу. Если после обновления 3x-ui поменяется вёрстка
  страницы Clients, селекторы в `xui_client.py` придётся поправить.
- «Select all» привязывает клиента ко всем inbound'ам.

## Установка на Ubuntu

1. Скопируйте на сервер все файлы в одну директорию, например `/opt/xui-discord-bot`.

2. Заполните `.env` (скопируйте из `.env.example`):
   ```bash
   cd /opt/xui-discord-bot
   cp .env.example .env
   nano .env
   ```
   Обязательно укажите `DISCORD_TOKEN`, `XUI_BASE_URL`, `XUI_USERNAME`, `XUI_PASSWORD`,
   `XUI_INBOUND_ID`, `XUI_SUB_BASE`.

3. Запустите установку:
   ```bash
   sudo bash install_ubuntu.sh
   ```
   Скрипт поставит `python3-venv`, создаст `.venv`, установит зависимости,
   **проверит подключение к 3x-ui** (`test_connection.py`) и, если всё ок,
   создаст и запустит systemd-сервис `xui-discord-bot` с автозапуском.

## Проверка подключения к 3x-ui отдельно (рекомендуется перед первым запуском)

Прежде чем разбираться с Discord, убедитесь, что бот вообще может залогиниться в панель:

```bash
cd /opt/xui-discord-bot
source .venv/bin/activate
playwright install --with-deps chromium   # один раз, если ещё не делали
python test_connection.py
```

Скрипт откроет headless-браузер, попробует залогиниться и покажет итоговый URL
после отправки формы (если осталось `/login` в адресе - значит логин не прошёл,
скорее всего неверный пароль) плюс фрагмент HTML для диагностики.

## Управление сервисом

```bash
sudo systemctl status xui-discord-bot      # статус
sudo systemctl restart xui-discord-bot     # перезапуск после правки .env
sudo journalctl -u xui-discord-bot -f      # логи в реальном времени
tail -f /opt/xui-discord-bot/bot.log       # логи в файл
```

## Настройка XUI_WEB_BASE_PATH

Откройте панель в браузере и посмотрите на адресную строку:

- `https://host:port/` (без доп. пути) → `XUI_WEB_BASE_PATH=` оставьте пустым.
- `https://host:port/aBc123XyZ/` (случайный путь) → впишите `XUI_WEB_BASE_PATH=aBc123XyZ`
  (без `/login`, без начального/конечного слэша).

## Диагностика 403 при логине

Если `test_connection.py` показывает `403`, по порядку проверьте:

1. **Логин/пароль верны?** Проверьте, зайдя в панель в браузере теми же данными.
2. **XUI_WEB_BASE_PATH указан правильно** — см. выше.
3. **fail2ban не забанил IP сервера**, откуда стучится бот:
   ```bash
   sudo fail2ban-client status
   sudo fail2ban-client status <имя_jail>
   sudo fail2ban-client set <имя_jail> unbanip <IP>
   ```
4. Если ничего не помогло — пришлите вывод `test_connection.py` целиком, там
   есть код ответа и первые 200-300 символов тела ответа панели, по ним видно,
   что именно её не устраивает.

## Ограничения и что стоит доработать под продакшен

- Если панель на HTTPS с самоподписанным сертификатом — `XUI_VERIFY_SSL=false`
  отключает проверку сертификата. Для продакшена лучше настроить нормальный сертификат
  (например, через Let's Encrypt) и поставить `XUI_VERIFY_SSL=true`.
- SQLite подходит для одного инстанса бота; при масштабировании — Postgres/MySQL.
- Сейчас на пользователя — одна подписка (`discord_id` уникален в таблице).
